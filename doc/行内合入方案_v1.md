#### 3.1.1 java —— agent 三菜单整包（351 个）

`src/main/java/com/suzhou/bank/agent/**` **整目录搬**，包含：

## 7. 版本管理机制（曹哥后续要维护行内 / 行外两条线）

### 7.1 核心难点

| 难点 | 说明 |
|---|---|
| 行内**无共同 git 历史**（单提交快照） | ⛔ 不能 `git diff`、不能 `merge`、不能 `cherry-pick` |
| 行内会被**行内团队继续演进** | 下次合入时，行内基线可能已变 → **必须先检测漂移** |
| 外网**持续开发** | 每次合入都要知道「上次合到哪个提交」 |

### 7.2 建议机制：**双锚点 + 台账**

**锚点 1（外网侧）**：在 `bosz-agent-backend` 打 git tag
```
intranet-sync-20260920      ← 本次合入的外网基点
```
下次增量：`git diff intranet-sync-20260920..HEAD --stat` → 得到外网侧新增/改动文件

**锚点 2（行内侧）**：对**已合入的文件**记 **SHA1 台账**（剥离 CRLF/BOM 后）
```
doc/行内同步台账.md
  | 文件 | 外网版本(tag) | 合入后行内 SHA1 | 合入日期 |
```

**台账的三个用途**：
1. **漂移检测**：下次合入前，重算行内文件 SHA1，与台账不符 ⇒ **行内被改过** → 该文件需**三方比对**（行内新版 vs 外网新版），不能直接覆盖
2. **增量计算**：`外网新 SHA1 ≠ 台账 SHA1` ⇒ 该文件外网侧有新改动 → 需合入
3. **回滚依据**：知道每个文件从哪来、什么状态

### 7.3 每次增量合入的标准流程（5 步）

```
① 镜像两端 src/main → D:\wb_cmp\{be_in,be_out}（robocopy /MIR）
② 算 SHA1 三向比对：
     行内现态 vs 台账基线   → 检测行内漂移
     外网现态 vs 台账基线   → 得到外网增量
③ 分类：
     agent 包整目录      → 直接整包覆盖（它是外网专属，行内不会改）
     共有文件            → 逐项摘增量（报告相关以行内为准）
     行内独有            → 不碰
④ 合完：编译验证（行内跑 mvn）+ 更新台账 SHA1 + 打外网新 tag
⑤ 出一份本次合入的 diff 报告（不自动提交）
```

### 7.4 目录约定（建议）

```
bosz-agent-backend/
  doc/行内合入方案_v1.md          ← 本文件（方案）
  doc/行内合入_清单_v2.md          ← 每次合入执行时生成的「逐文件清单」
  doc/行内同步台账.md              ← SHA1 台账（漂移检测依据）
```

## 9. 比对脚本（可复现）

```powershell
function HashOf([string]$p){
  $b=[System.IO.File]::ReadAllBytes($p); $s=0
  if($b.Length -ge 3 -and $b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF){ $s=3 }
  $ms=New-Object System.IO.MemoryStream
  for($i=$s;$i -lt $b.Length;$i++){
    if($b[$i] -eq 13){ if(($i+1) -lt $b.Length -and $b[$i+1] -eq 10){ continue } else { $ms.WriteByte(10); continue } }
    $ms.WriteByte($b[$i])
  }
  $sha=[System.Security.Cryptography.SHA1]::Create()
  return ([System.BitConverter]::ToString($sha.ComputeHash($ms.ToArray()))).Replace('-','')
}
```
