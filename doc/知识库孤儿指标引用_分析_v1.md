## 四、附带发现（复核时顺手扫出来的）

### 4.1 还有 5 条「知识库已删、但指标还在」的悬空关联

除上面那 11 条外，另有 4 个已删知识库仍留着关联记录（指标本身还存在）：

| 已删知识库 ID | 关联记录数 |
|---|---|
| `2094366118006304770` | 2 |
| `2096853378031169538` | 1 |
| `2095813569355460609` | 1 |
| `2096858264869285890` | 1 |

⇒ 与 B 类合起来看：**`knowledge_relate_index` 里挂到已删知识库的记录共 16 条**（11 + 5）。

### 4.2 关联表规模与重叠

| 表 | 行数 | 孤儿引用 |
|---|---|---|
| `knowledge_relate_index`（知识库 → 指标） | 496 | 13 |
| `index_relate_knowledge_info`（指标 → 知识库） | 492 | 15 |
| `knowledge_relate_index_version`（历史版本） | **0（空表）** | — |
| `index_params_version`（指标版本） | **0（空表）** | — |

- 两表重叠 **475 条 / 496**（约 96%）⇒ **基本是同一批关联记录的两个方向**，清理时要**两张表一起动**，只清一张会留另一半。
- 版本表都是空表 ⇒ **没有历史版本可回溯**，无法从版本表恢复被删指标的定义。

### 4.3 第三处引用点：`knowledge_base_params.relate_index_set`

73 个知识库的 `relate_index_set`（JSON，共 76 KB）里内嵌了 `paramNo` 引用。
逐个解析后：**孤儿引用仅 1 条**（`2095136676767612929`，属于上面 A 类第 4 条），已包含在 15 个之内，无新增。

### 4.4 这些编号确实是「被删的指标」，不是「编号写错」

已排除两种误判可能：

| 排查项 | 结果 | 结论 |
|---|---|---|
| 是否把 `paramid` 误当 `paramno` 引用 | `index_params.paramid` 命中 **0** | 不是引用写错列 |
| 是否命中其他列（`fromparamno` / `parentparamno` / `modelno`） | 全部命中 **0** | 不是引用别处 ID |
| 编号风格 | 15 个里 12 个为雪花 ID（与现存 718 个 `paramno` 同风格） | 确为 `index_params.paramno` 口径 |
| 是否曾在 9-16 备份中存在 | `bak_20260916_index_params`（920 行）命中 **3** 个：`202609031712187` / `202609031712188` / `20260903195039195` | 确有指标被删；其余 12 个未见该快照（快照仅覆盖 9-16 时点，不代表从未存在） |
| 9-16 备份有、现在没有的指标总数 | **10** 个 | 被删指标规模与孤儿数（15）同量级，可信 |

## 五、复核用 SQL（只读）

```sql
-- 15 个孤儿指标的统一清单（含知识库归属与来源表）
SELECT t.idx_no, t.src, t.kb_id, t.kb_name, t.idx_name
  FROM (
        SELECT k.index_no AS idx_no, 'K2I(知识库->指标)' AS src,
               k.knowledge_id AS kb_id,
               COALESCE(kb.paramname, '(知识库已删除)') AS kb_name,
               MAX(k.index_name) AS idx_name
          FROM knowledge_relate_index k
          LEFT JOIN index_params p ON p.paramno = k.index_no
          LEFT JOIN knowledge_base_params kb ON kb.paramid = k.knowledge_id
         WHERE p.paramno IS NULL
         GROUP BY k.index_no, k.knowledge_id, COALESCE(kb.paramname, '(知识库已删除)')
        UNION ALL
        SELECT r.param_no, 'I2K(指标->知识库)',
               COALESCE(r.relate_knowledge_no, '(无)'),
               COALESCE(r.relate_knowledge_name, r.relate_knowledge_code, '(无)'),
               '(关联表未存名称)'
          FROM index_relate_knowledge_info r
          LEFT JOIN index_params p ON p.paramno = r.param_no
         WHERE p.paramno IS NULL
       ) t
 ORDER BY t.idx_no, t.src;
```

```sql
-- 已删知识库留下的悬空关联
SELECT k.knowledge_id, count(*) AS rows_cnt
  FROM knowledge_relate_index k
  LEFT JOIN knowledge_base_params kb ON kb.paramid = k.knowledge_id
 WHERE kb.paramid IS NULL
 GROUP BY k.knowledge_id
 ORDER BY rows_cnt DESC;
```
