  贷后报告 · 模板层结构关系图（V2）
  目录表 × 内容块表 ｜ 当前线上模板：58 目录 / 188 块
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━


【一】全景：两层结构
┌──────────────────────────────────────────────
│  模板层（配置）
│     目录表 + 内容块表
│     定义整份报告的目录树、以及每个块的类型与来源
│     全报告共用一份
│
│        │  生成时按 blockCode 快照
│        ▼
│  实例层（数据）
│     内容实例 + AI 风险实例
│     存"这一份报告"实际填进去的正文
│
│        │  前端渲染
│        ▼
│  详情页
│     目录名当标题 → 块按类型渲染成 文本 / 表格 / 溯源按钮
└──────────────────────────────────────────────


【二】两张表 · 字段与关联
┌──────────────────────────────────────────────
│  目录表  app_report_catalog        （58 条 · 报告目录树）
├──────────────────────────────────────────────
│     catalogCode ...... 目录编号（唯一）            ★ 关联键
│     catalogName ...... 目录名称  ← 标题文案就在这
│     catalogLevel ..... 目录级别 1 / 2 / 3
│     parentCode ....... 上级目录（自关联；一级为 NULL）
│     sortNo ........... 同级排序
│     isEnabled ........ 是否可用 1 / 0
│
│              │
│              │   catalogCode      N : 1
│              │   一个块属一个目录
│              ▼
│
│  内容块表  app_report_content_block   （188 条 · 正文内容块）
├──────────────────────────────────────────────
│     blockCode ........ 块编号（唯一）
│     catalogCode ...... 所属目录 → catalog.catalogCode   ★ 关联键
│     fillType ......... 填充类型（长什么样）
│     analysisType ..... 分析类型（内容从哪来）
│     agentCode ........ 智能体编码（取数 / 规则标识）
│     agentParams ...... 调参 / 链接溯源令牌
│     blockName ........ 块名称
│     titleLevel ....... 标题级别            [ 已基本废弃 ]
│     emptyStrategy .... 空数据策略：占位 / 隐藏
│     jumpAnchorCode ... 跳转目标块（自关联）
│     sortNo ........... 同目录内排序
│     isEnabled ........ 是否可用 1 / 0
└──────────────────────────────────────────────


【三】关联关系 · 共三条（全靠 code 值，无数据库外键）
┌──────────────────────────────────────────────
│  ① 目录 ↔ 目录            自关联成树
│        parentCode  →  catalogCode（父目录）
│        一级目录 parentCode = NULL，靠 catalogLevel 分 1/2/3 级
│
│  ② 内容块 → 目录          N : 1        ★ 核心关联
│        block.catalogCode  →  catalog.catalogCode
│        一个目录挂 N 个块，按同目录内 sortNo 渲染
│        ⚠ catalogCode 可为 NULL = 报告级块（报告头），不进目录树
│
│  ③ 内容块 ↔ 内容块        自关联
│        jumpAnchorCode  →  目标块 blockCode
│        单向跳转（点本块滚到目标块），与类型无关，无跳转则 NULL
└──────────────────────────────────────────────


【四】★ 最关键：一级 / 二级 / 三级标题住在哪？
┌──────────────────────────────────────────────
│   标题不是"块"，是"目录"。块表里没有章节标题块。
│
│   标题 ──►  目录表  app_report_catalog
│              按 catalogLevel 分 1 / 2 / 3 级
│              文案 = catalogName ｜ 顺序 = 同级 sortNo
│
│   内容 ──►  内容块表  app_report_content_block
│              188 个块挂在目录下（N : 1）
│              块表里唯一的 TITLE = "报告主标题"（catalogCode = NULL）
└──────────────────────────────────────────────

【六】往下游：实例层怎么接
┌──────────────────────────────────────────────
│  ◆ 快照机制
│       生成报告时按 blockCode 把模板配置快照进实例表
│       不建指向模板表的物理外键
│       ⇒ 模板改版不影响历史报告
│
│  ◆ agentParams 特例
│       实例表不存 agentParams
│       详情接口按 blockCode 从模板表内存补
│       （同一 agentCode 在借款人 / 担保人章节入参不同）
└──────────────────────────────────────────────


【七】使用口径 · 红线
┌──────────────────────────────────────────────
│  ⚠ 无物理外键          关联全靠 code 值；唯一性靠两个唯一索引
│                        uk_report_catalog_code / uk_report_block_code
│  ⚠ catalogCode 可为 NULL  只有"报告头三兄弟"不进目录树，join 别把它们丢掉
│  ⚠ 加 V2_ 前缀是硬要求  旧模板行是置 isEnabled=0 保留，不加前缀会撞唯一键
│  ⚠ 溯源不看 fillType    走 analysisType：TRACE_TABLE / TRACE_LINK
│  ⚠ 标题别做成块         章节标题一律进目录表；块里再配 TITLE 是重复渲染
└──────────────────────────────────────────────
