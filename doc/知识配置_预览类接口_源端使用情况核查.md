## 一、一句话结论

**你的判断是对的 —— 这 4 个接口在源端实际上都不会被触发**：

- **3 个是死代码**（`tracePreview` / `imagePreview` / `wholeSourcePreview`）：只被**已废弃的 V1 弹窗**调用，
  而知识配置页用的是 **V2**；
- **1 个是活代码但零数据**（`resource/preview`）：入口标签靠 `resourceFlag=true` 渲染，
  而 **86/86 条数据的 `resourceFlag` 全是 `false`** → 标签永不出现 → 接口永不被调用。

所以本工程**不接线它们是正确的**，不是漏做。

## 三、证据细节

### 3.1 「V1 已废弃」怎么证明的

源工程同一功能有两个文件：

| 文件 | `name` | 谁引用它 |
|---|---|---|
| `views/knowledge/components/KnownConfigModal.vue` | `KnownConfigModal` | **无人引用** ← 搜索 `knowledge/components/KnownConfigModal.vue` 全仓 0 命中 |
| `views/knowledge/components/KnownConfigModalV2.vue` | `KnownConfigModal`（名字相同！） | `KnownList.vue`、`knowledgeAnalysis/components/KnowledgeDetail.vue` —— **导入时就是别名 `KnownConfigModal`** |

也就是说：**文件名带 V2 的那个才是线上用的**，而 `ImageConfigModal` / `WholeSourceConfigModal` /
`TraceabilityConfigModal` 这三个组件**只被不带 V2 的那个引用** → 整条链是死代码。

> 实证：`Grep "ImageConfigModal|WholeSourceConfigModal|TraceabilityConfigModal"` 的命中全部落在
> `KnownConfigModal.vue`（V1）文件内；`KnownConfigModalV2.vue` 的 import 列表里没有它们。

### 3.2 `resource/preview` 为什么"有代码没数据"

`PromptConfigItem.vue` 第 61 行才是溯源面板的入口：

```html
<a-tag color="blue" v-if="hasTraceAbility && showTrace" @click="showConfig = true">溯源配置</a-tag>
```

而 `hasTraceAbility` 只在一个地方被置真（第 277~280 行）：

```js
created() {
  if (this.formInfo && this.formInfo.resourceFlag == true) {
    this.hasTraceAbility = true
  }
}
```

`formInfo` 来自条件组 JSON（即 `knowledge_base_params.prompt` / `contentdesc`）。两库实测：

| 检查项 | 公司库 | 本地库 |
|---|---|---|
| `prompt` 含 `resourceFlag` | 86 / 86 | 86 / 86 |
| `prompt` 含 **`resourceFlag":true`** | **0** | **0** |
| `prompt` 含 `resourceFlag":false` | **86** | **86** |

→ **标签永不渲染 ⇒ `ConfigTraceability` 永不挂载 ⇒ `/resource/preview` 永不被调用。**

（另一条链路 `TargetTraceItem` 同样依赖溯源数据，且 `trace_status='Y'` 为 0，结论一致。）

## 四、本工程的处理建议

| 接口 | 建议 | 理由 |
|---|---|---|
| `/tracePreview`、`/imagePreview`、`/wholeSourcePreview` | **不接线（维持现状）**，并在 api 层标注「源端死代码」 | 源端自己都不用；接上去也没数据可测 |
| `/resource/preview` | **保持"接口已定义、UI 未接"**；仅当业务确认要启用「溯源」能力时再补 | 需要同时满足三件事才有意义：① 业务给出 `resourceFlag=true` 的数据；② 补 `trace_config` 等配置；③ 溯源配置 UI 做到与源端一致（含卡片式子项编辑、复制开关、查询分页） |

> 本工程后端 4 个接口的 Controller/Service **均已实现**（`KnowledgeBaseConfigController`
> 第 151/157/163/169 行），因此将来要启用只是"前端接线"的事，不涉及后端改造。
