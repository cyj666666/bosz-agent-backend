**原状态（真 bug）**：切模型只改 `largeModelCode`、**不换出该模型的输出要求** →

**交付物**：`src/agent/pages/knowledge-config/KnowledgeConfigEditor.tsx`（单文件）

- [ ] 编辑输出要求 → 立即写回该模型那一份（map）
- [ ] 保存后重新打开 → 切模型显示仍正确（不串份）
- [ ] 右栏「模型配置」4 个字段可见可改：**top概率(0~1) / 温度(0~2) / 是否输出思考 / 系统提示词**
- [ ] 切模型时这 4 个字段同步换成该模型那一份
- [ ] `largeModelParam` 为空 map 时**不提交**（避免抹掉库中已有参数）
- [ ] `elseCondition`（ELSE 分支）与「用户提示词」**不参与分模型**（与源一致）
- [ ] 左侧指标树/规则树点选，能插入到**当前聚焦的编辑区**（含右栏「系统提示词」）

## 第 7 项 — 智策引擎走本工程自有大模型端到端跑通（P4 实测）

**原状态**：`parseRule` 用源厂商智能体。

**交付物 / 改动**
- 后端 `parseRule` 改用本工程 `large_model_config` 里的大模型

- 新增 `normalizeMetricRefs` + `replaceBareMetricCodes`：把裸编号补成 `{编号|名称}`
  （源 `parseRule` 只替换"指标名称"，而 P4 提示词让模型输出"编号"→ 原替换空转、留下裸编号）

**验收点**
- [ ] `POST /api/agent/rule/parse` → HTTP 200
- [ ] 返回 `parsedExpression` 格式为 `{编号|名称}`（与前端「从指标树插入」的 `&&{编号|名称}` 约定一致）
- [ ] 多条件表达式拼接正确

**实测结果（已跑通）**
```json
{"code":200,"data":{"parsedExpression":"{900001|近12个月逾期次数} > 3 || {900002|资产负债率} > 70"}}
```
（HTTP 200 / 约 4 秒；测试指标 `900001~900005` 为当时插入，可按需删除）

**同轮修掉的 3 个真 bug（影响面比第 7 项本身更大）**
1. 🔴🔴 **hutool `body(x, "UTF-8")` 会把 Content-Type 覆盖成 `UTF-8`**（第二参是 contentType，不是 charset）
   → 全工程 **7 处**已统一改为 `"application/json;charset=utf-8"`。**凡大模型/外呼 HTTP 调不通，先查这条。**
2. 🔴 **`CallLlmUtil` 无条件 AES 解密 api_key**，与"明文"约定冲突 → 抽 `resolveApiKey` 兼容明文/密文。
3. 🔴 `body()` 写错会**伪装成 JSON 解析失败**（服务端返回纯文本，被 fastjson 再抛一次）→ 排查口径已记录。
