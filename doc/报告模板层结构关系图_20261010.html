三、关联关系共三条 全部靠 code 值，无数据库外键
关系字段基数说明
目录 ↔ 目录 parentCode → catalogCode 树 目录表自关联成一棵树；一级目录 parentCode = NULL，靠 catalogLevel 分 1/2/3 级。
内容块 → 目录 block.catalogCode → catalog.catalogCode N : 1 核心关联。一个目录挂 N 个块，按同目录内 sortNo 渲染。
⚠️ catalogCode 可为 NULL = 报告级块（报告头），不进目录树。
内容块 ↔ 内容块 jumpAnchorCode → 目标块 blockCode 自关联 单向跳转（点本块滚动到目标块）。与类型无关，无跳转则 NULL。
四、最关键的一点：一级 / 二级 / 三级标题住在哪？
标题不是"块"，是"目录"。块表里没有章节标题块。 报告的各级标题，是目录表里的记录（catalogLevel = 1 / 2 / 3），标题文案存在 catalogName； 内容块表里不存在一级 / 二级 / 三级标题块 —— 块只负责"标题下面那坨内容"。

✅ 标题 → 目录表 app_report_catalog

58 条目录里，按 catalogLevel 分 1/2/3 级；
文案 = catalogName；顺序 = 同级 sortNo。

📦 内容 → 内容块表 app_report_content_block

188 个块挂在目录下，N:1；
块表里唯一的 TITLE 是"报告主标题"（catalogCode = NULL）。

六、往下游：实例层怎么接
快照机制 生成报告时按 blockCode 把模板配置快照进内容实例 / AI 风险实例，不建指向模板表的物理外键 ⇒ 模板改版不影响历史报告。
agentParams 特例 实例表不存 agentParams；详情接口按 blockCode 从模板表内存补（同一 agentCode 在借款人/担保人章节入参不同）。
七、使用口径 · 红线
  • 无物理外键 —— 关联全靠 code 值；唯一性靠 uk_report_catalog_code / uk_report_block_code 两个唯一索引保证。
  • catalogCode 可为 NULL —— 只有"报告头三兄弟"（主标题 / 副标题 / 说明）是报告级块，不进目录树；join 时别 inner join 把它们丢了。
  • 加 V2_ 前缀是硬要求 —— 旧模板行是置 isEnabled=0 保留而非删除，不加前缀会撞唯一键。
  • 溯源不看 fillType 了 —— 走 analysisType：表格溯源 = TABLE + TRACE_TABLE，链接溯源 = TEXT + TRACE_LINK；SOURCE_LINK 是僵尸枚举。
  • 标题别想做成块 —— 章节标题一律进目录表（catalogName），块表里再配 TITLE 块是重复渲染。
