## 4. 🔴 已验证的关键坑

**坑 1：空块前置判断会把 `TRACE_LINK` 直接吞掉（已规避）**
`useReportInstance.ts` 的 `blockToHtml` 里，「空内容」判断在 `TRACE_TABLE`/`TRACE_LINK` 分支**之前**：

```ts
const content = String(block.content ?? '').trim();
if (!content) { /* HIDE → '' ；PLACEHOLDER → 暂无数据 */ }
```

`TRACE_LINK` 的 `content` **恒空**（链接实时换取、不落库）⇒ 必然被判空块。
**必须在它之前开例外**，否则后面写了分支也永远走不到。

**坑 2：不能用 `SOURCE_LINK` 表达溯源**（2026-09-17 已定）
`SOURCE_LINK` 的 content 会被渲染成 `<a href="${content}">` ⇒ 类型交给 `analysisType` 维。

**坑 3：外网无法真跑**（见 §3.3）。

**坑 4：链接一次性 + 1h** ⇒ 前端**不预加载、不缓存**；一次只允许一个在途请求（`traceLinkLoading`）；失败给 toast 让用户重点。

**坑 5：`pageParams` 前端不传** —— 由后端 `LinkTraceParamBuilder` 按 `shareCode` **实时装配**（方案 B，19:1x 已实施）。
前端只传 `shareCode / reportNo / blockCode / guarantorName`。

**坑 6：实例表没有 `agentParams` 列 ⇒ 前端多担保人按钮"写了但走不到"（已修，零 DDL）**
`app_report_content_instance` 只有 `content` / `agentCode` / `blockName` 等，**没有 `agentParams`**
⇒ 详情接口不返回它 ⇒ 前端 `block.agentParams` 恒 `undefined` ⇒ 退化为单按钮。
**修法**：在 `detail()` 里从**模板表** `app_report_content_block` 按 blockCode **内存合并**补上
（复用已加载的 `loadEnabledBlocks()`，零额外查询、零 DDL）。

**坑 7：参考 sql 文件的 DDL 可能过期** —— 外网 `20260819/源表层/信贷/对公检查信息查询接口_建表DDL.sql`
仍是 12 列，行内已 17 列（多了 `baSerialNo` / `electroApproveSerialNo` / `approveApplyType`）。
**行内 DDL 才是准的**，外网这份要同步。
