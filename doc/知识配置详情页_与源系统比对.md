## 二、问题 1：模型信息为什么是 `Qwen3-32B`

### 现象
知识库「配置 → 详情页」右栏「输出要求 → **模型信息**」下拉显示 `Qwen3-32B`，
但本地库 `large_model_config` **只有一条** `bosz-report-ai`（`model=deepseek-flash`）。

### 根因（已实证）
「模型信息」不是取自 `large_model_code` 字段，而是取自**条件组 JSON 里嵌套的字段**：

```
内容在 knowledge_base_params.contentdesc 的深处：
  ..."usePrompt":"","modelInfo":{"largeModelCode":"Qwen3-32B"}},"id":"8413a513-..."}]
```

`large_model_code` 字段本身**已正确**（86/86 = `bosz-report-ai`），但条件组里的 `modelInfo.largeModelCode`
**还是公司库的旧值**。原来的 `05_映射改写.sql` 第 ③ 步只替换了**带冒号的 key 形态**：

```sql
replace(large_model_content, '"Qwen3-32B":', ...)   -- 只匹配 key
```

而嵌套 value 的形态是 `"largeModelCode":"Qwen3-32B"`（后面跟 `}` 或 `,`，**没有冒号**）→ **匹配不到**。

### 公司库 vs 本地 —— 对称证据（说明这是"没翻译完"，不是配置错）

| 检查项 | 公司库 `172.20.2.19:8000` | 本地 `127.0.0.1:5432` |
|---|---|---|
| `large_model_config` 有几条 | **1 条**：`Qwen3-32B`（model=`default`, lm_name=`qwen3-32b`, use_flag=Y） | **1 条**：`bosz-report-ai`（model=`deepseek-flash`, lm_name=贷后管理智能体专用, use_flag=Y） |
| 存在 `bosz-report-ai` 吗 | **0**（公司库压根没这个 code） | 就是它 |
| `knowledge_base_params.large_model_code` | `Qwen3-32B` **86/86** | `bosz-report-ai` **86/86** ✅ 已翻译 |
| `contentdesc` 里嵌套的 `modelInfo.largeModelCode` | `Qwen3-32B` **86** | `Qwen3-32B` **86** ❌ 漏翻译 |
| `input_condition` 里嵌套的 | `Qwen3-32B` **27** | `Qwen3-32B` **27** ❌ 漏翻译 |
| `contentdesc` 里出现过 `bosz-report-ai` 吗 | **0** | — |

**结论**：`Qwen3-32B` 是**公司环境的历史配置**（公司库 `large_model_config` 就那一条），
随 `knowledge_base_params` 整表导进本地。迁移时本应把「公司口径 → 本平台口径」全部翻译，
但只翻译了 **2/3**（字段 ✅、JSON key ✅、**JSON 里嵌套的 value ❌**）——
你在页面上看到的就是那**没翻译完的 1/3**。**你本地的 `large_model_config` 没问题。**

> 同一份数据里，模型 code 存了**两处**：表字段 + JSON 载荷；而 JSON 载荷又有**两种形态**（key / 嵌套 value）。
> 只按一种形态写 replace，就必然漏 —— 这是本次踩坑的本质。

### 残留实测（本地 `as_agent`，精确 `count(*)`）

| 列 | 含 `Qwen3-32B` 的行数 | 形态 |
|---|---|---|
| `knowledge_base_params.contentdesc` | **86 / 86** | `"largeModelCode":"Qwen3-32B"` |
| `knowledge_base_params.large_model_content` | **86 / 86** | 转义形态 `\"largeModelCode\":\"Qwen3-32B\"` |
| `knowledge_base_params.input_condition` | **27** | `"largeModelCode":"Qwen3-32B"` |
| `large_model_content` 的 **key** 形态残留 | **0** | （③ 步已改对） |
| 小写 `qwen3` 残留（contentdesc） | **0** | — |

> 顺带确认：`user_prompt` / `prompt` / `black_content_desc` / `black_model_code` 都**没有**残留。

### 为什么"看着像 bug"
前端「模型信息」下拉的候选项来自 `large_model_config`（只有 `bosz-report-ai`），
而回显值是 `Qwen3-32B` —— 一个**不在候选列表里**的值，所以看得很刺眼。

### 已做的修复
| 文件 | 改动 |
|---|---|
| `三个菜单_交付包/DML/05_映射改写.sql` | 新增第 **④** 步：对 `contentdesc` / `input_condition` / `large_model_content`（参数表）与 `content_desc` / `input_condition` / `large_model_content`（版本表）做**裸串 replace**，一次覆盖 key 与 value 两种形态 |
| `三个菜单_交付包/DML/07_校验.sql` | 【二】段新增「④ 嵌套 largeModelCode 残留（期望 0）」+「新模型 code 命中（期望 86）」 |
| `sql/本地自测/修复_模型编码残留_Qwen3-32B.sql` | 本地库修复脚本（**已备好，待授权执行**） |

> ⚠️ 交付包这份如果不修，**现场导完数据同样会显示 `Qwen3-32B`** —— 这是本轮最有价值的发现。

## 三、问题 2：「请求参数」缺少编辑

### 源系统怎么做（`TestSet.vue`）
「测试集」下拉的**每个选项 hover** 时出现两个图标：

| 图标 | 行为 | 接口 |
|---|---|---|
| ✏️ 编辑 | 打开 `SaveTestSetModal(isEdit=true)`：**改名 + 用当前参数列表覆盖该测试集** | `editTestSet({id, inputParamName, inputParam})` |
| 🗑️ 删除 | 确认后删除整个测试集 | `deleteTestSet([id])` |

### 本工程原来缺什么
`TestSetPanel.tsx` 已有：选择测试集 / 「另存为测试集」/「删除测试集」/ 参数行增删改。
**唯独没有「编辑」** —— `api/knowledgeConfig.ts` 里的 `editTestSet` **定义了但全仓零调用**。

### 后端是现成的
```
POST /api/agent/knowledgeRelateInputParam/edit
→ KnowledgeRelateInputParamController#edit → updateById
```
所以这是**纯前端漏接线**，不是接口缺失。

### 已修
`TestSetPanel.tsx`：
- 引入 `editTestSet`，新增「**编辑测试集**」按钮（未选测试集时禁用，与「删除测试集」同一排）
- 点开 → 弹窗预填当前名字（必填）→ 保存 = `editTestSet({id, knowledgeId, inputParamName, inputParam: JSON.stringify(当前参数列表)})`
  —— 与源系统语义一致：**改名 + 用当前参数覆盖**
- 验证：`tsc -b --force` **0 错误**；`vite build` **成功**

> 💡 交互差异（有意）：源系统把 ✏️/🗑️ 藏在**下拉选项的 hover** 里；本工程做成**按钮**，
> 避免引入全局 hover CSS、零回归风险。**能力等价**。你要严格照源系统的 hover 图标，我再改。
