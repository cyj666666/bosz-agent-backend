## 二、执行顺序

### 第 0 步（必做）：设定 schema
```sql
SET search_path = <你的schema>, public;
```
> 交付脚本里**表名全是裸名（不带 schema 前缀）**，全靠这句定位；换任何 schema 名都能用。

### 第 1 步：建表 —— 执行 `DDL/00_全部44张_一次性执行.sql`
> **表已建好就跳过整块。** 脚本无外键、无序列依赖；**没有 `IF NOT EXISTS`**（表已存在会直接报错，属预期）。
> 3 条原 MySQL 风格 `MODIFY COLUMN` 加宽语句**已内联进列定义**，脚本内已无 `ALTER`。

### 第 2 步：导数据 —— 按 01 → 04 顺序执行

| 文件 | 行数 | 内容 |
|---|---|---|
| `01_数据_基础配置_字典.sql` | 112 | 字典（下拉选项来源） |
| `02_数据_指标配置.sql` | 1618 | 指标分组树 + 指标 + 指标↔知识库关联 |
| `03_数据_知识配置.sql` | 1104 | 知识库分组 + 知识库 + 版本 + 知识库↔指标关联 + 测试集 |
| `04_数据_智策引擎.sql` | 42 | 智策引擎规则 |

### 第 3 步（必做）：`05_映射改写.sql`
把数据里的**公司口径**改成**目标环境口径**。全部用**子查询自动取值，不需要手工替换**：
- `index_params.script` 里的数据源 id → 目标库的那条数据源
- `knowledge_base_params` / `_version` 的 `large_model_code` → 目标库启用中的模型
- `large_model_content` 的 **JSON key** 同步换（不换会导致编辑器取不到「输出要求」并静默覆盖数据）

### 第 4 步（必做）：`06_授权生成.sql`
给 `admin` 生成 `sys_role_knowledge`（全部分组）+ `sys_role_knowledge_output`（全部知识库）。

> 🔴 **不跑这一步，admin 打开「知识配置」是空白页** —— 知识库的**分组树和列表**都走
> `sys_role_knowledge` 过滤，查不到就直接返回 0 条，而代码里**对 admin 没有豁免**
> （只有指标侧有 `role-filter-bypass-roles: [admin]`）。

### 第 5 步：`07_校验.sql`
照跑，逐项对「实际值 / 期望值」。重点：
- 数据行数是否齐（第 【一】 段）
- **三处「残留」必须为 0**（旧数据源 id / 旧模型 code / 旧 JSON key）
- **两条授权必须非空**（= 分组总数 / 知识库总数）

## 五、注意事项

1. **编码统一 UTF-8**（数据文件含中文）。
2. **多行 INSERT 是合法 SQL**：`rule_text` / `script` 等字段含换行，所以一条 INSERT 可能占多行。
   用 **DBeaver / Navicat / psql / gsql** 执行都没问题；
   若用自研脚本执行，请确认它**不做"按分号或按行简单切分"**（那样会把语句切碎、报 `Unterminated string literal`）。
3. **幂等性**：数据文件是纯 `INSERT`，**目标表已有同主键数据时会冲突**。
   要重跑：先 `DELETE FROM <表> WHERE <主键> NOT IN (<要保留的>)`，再重导。
   ⚠️ 目标库**不支持** `INSERT ... ON CONFLICT DO NOTHING`（那是 PG 9.5+ 语法，openGauss 基线是 9.2）。
4. **`sys_data_source` / `large_model_config` 的数据不在本包** —— 属于「本平台配置」，见 `DML/00_基础配置_模板.sql`。
5. **`06_授权生成.sql` 用 `md5(...)` 造主键并带 `NOT EXISTS`**，可重复执行（幂等）。
6. ⛔ 不要执行仓库里的 `sql/agent/agent_gauss_ddl.sql`（179 张全量，含 130 张无关表）
   与 `sql/agent/agent_模块建表_as_agent.sql`（39 张旧子集，**且不含 3 条加宽语句**）—— 已被本包 DDL 取代。
