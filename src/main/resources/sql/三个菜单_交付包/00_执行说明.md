## 五、注意事项

1. **编码统一 UTF-8**（数据文件含中文）。
2. **多行 INSERT 是合法 SQL**：`rule_text` / `script` 等字段含换行，所以一条 INSERT 可能占多行。
   用 **DBeaver / Navicat / psql / gsql** 执行都没问题；
   若用自研脚本执行，请确认它**不做"按分号或按行简单切分"**（那样会把语句切碎、报 `Unterminated string literal`）。
3. **幂等性**：数据文件是纯 `INSERT`，**目标表已有同主键数据时会冲突**。
   要重跑：先 `DELETE FROM <表> WHERE <主键> NOT IN (<要保留的>)`，再重导。
   ⚠️ 目标库**不支持** `INSERT ... ON CONFLICT DO NOTHING`（那是 PG 9.5+ 语法，openGauss 基线是 9.2）。
3b. 🔴🔴 **重导数据之后，必须重新执行 `05_映射改写.sql`！**
   数据文件 `01~04` 里存的是**公司口径**（`script` 里的数据源 id、`large_model_code`、
   `large_model_content` 的 JSON key），重导会把改写结果**整片覆盖**掉。
   典型症状（后端日志）：
   ```
   ERROR ... 数据源信息不存在,dataSourceId:2095447359636992001
   ```
   或智策引擎报「未找到大模型配置」。
   → **顺序永远是**：导数据 → 跑 `05_映射改写.sql` → `06_授权生成.sql` → `07_校验.sql`。
   （`05` 是幂等的，重复跑没副作用）
4. **`sys_data_source` / `large_model_config` 的数据不在本包** —— 属于「本平台配置」，见 `DML/00_基础配置_模板.sql`。
5. **`06_授权生成.sql` 用 `md5(...)` 造主键并带 `NOT EXISTS`**，可重复执行（幂等）。
6. ⛔ 不要执行仓库里的 `sql/agent/agent_gauss_ddl.sql`（179 张全量，含 130 张无关表）
   与 `sql/agent/agent_模块建表_as_agent.sql`（39 张旧子集，**且不含 3 条加宽语句**）—— 已被本包 DDL 取代。

> 🆕 **「AI分析」与「补充分析」的区别**（现场答疑用）：
> - **AI分析**（`IntelligentStrategyEngine`）：**一条通用**配置，素材来自入参，输出「事实 + 口径对照 + 提示」；
