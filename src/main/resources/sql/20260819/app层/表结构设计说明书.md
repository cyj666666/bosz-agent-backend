# 贷后检查报告数据表结构设计说明书

> **版本**：V1.0　**日期**：2026-08-22　**数据库**：高斯DB（GaussDB，兼容 MySQL 模式）
> **设计依据**：《数据映射细化V2.xlsx》（报告需求 437 条数据要素）
> **配套文件**：`app_贷后报告_建表脚本.sql`

---

## 一、背景与目标

本套表结构服务于**银行对公客户日常定期检查（贷后）报告**的 AI 生成。报告按 12 个章节 + AI 全文分析组织，每个章节下包含若干知识内容模块（Excel B 列），共 48 个模块区块、去重后约 159 个唯一字段。

**目标**：为每个 B 列模块提供对应的数据表，公司可在此基础上做二次设计（文案模板、规则引擎、表格组件均依赖本表结构取数）。企业维度（customerId）+ 报告维度（reportNo）+ 入库时间（inputtime）贯穿全部表。

## 二、设计原则

1. **存储按"业务实体"，不按"展现形式"分表。** 规则、文案、表格只是数据的三类消费方式（Excel D 列），同一字段（如"是否国资/国有担保"）在经验库规则里做判断、在正文文案里被引用、在表格里列出，只存一份。
2. **三层表体系：报告主表 → 公共基础表 → 模块明细表。** 跨模块复用的元属性/实体下沉到公共表，模块表只存自己的专属字段，通过 reportNo 关联。经验库规则不单独建表，其判断所需源数据来自公共/明细表。
3. **字段以 H 列数据要素为准、J 列取值字段为英文命名参考。** J 列为空或为"待确认/安硕加工/—"的，按 H 列中文转英文（驼峰风格）。

## 三、总体架构

```
┌─────────────────────────────────────────────┐
│ L1 报告层    app_report_info（1张）            │  一次贷后报告一条记录
├─────────────────────────────────────────────┤
│ L2 公共基础表（10张）                         │  跨模块复用的元属性与实体
│ 客户概况/工商登记/股东股权/授信用信/借据/      │  报表四件套、征信查询时间
│ 预警台账/押品/他项权利/结算账户/贷后意见       │  等高频要素只存一份
├─────────────────────────────────────────────┤
│ L3 模块明细表（20张）                         │  与B列模块一一对应
│ 财报主档/财务指标/纳税/征信快照/征信债务/      │  字段=该模块H列数据要素
│ 担保人×2/征信查询/资金回流/受托支付/           │
│ 交易对手/代发统计/检查打卡/批复要求/综合指标    │
└─────────────────────────────────────────────┘
       公共列贯穿全部表：id · reportNo · customerId · customerName · inputtime

说明：①风险经验库（C 列=经验库）模块不单独建规则表——规则判断所需源数据
均来自 L2/L3 的表（取数 SQL 见《数据映射细化V4.xlsx》各经验库模块），
规则命中逻辑与结果存储由公司规则平台自行设计。
②工商口径与系统口径分开存储：工商登记数据（法定代表人/注册资本/实缴/
受益人/国企标识等）集中在 app_ic_info（客户级），工商股东明细（股东名/
持股/股权变更）集中在 app_ic_shareholder_info（股东级），系统口径数据在
app_customer_info /
app_shareholder_info（实际控制人在 app_customer_info.actualController），
口径对比规则（如"工商受益人≠系统实控人"）分别取数后由规则引擎比较。
```

## 四、命名规范

| 项 | 规范 |
|---|---|
| 表名 | `app_<实体英文>_info`（如 app_shareholder_info） |
| 公共列 | `id BIGINT AUTO_INCREMENT` / `reportNo VARCHAR(64) NOT NULL` / `customerId VARCHAR(64)` / `customerName VARCHAR(128)` / `inputtime TIMESTAMP DEFAULT CURRENT_TIMESTAMP` |
| 字段名 | J 列有值→照搬（phaseOpinion、confirmTime、TOTAL_BAL…）；J 列缺→按 H 列中文转驼峰（revenueYoy、overdueTotal…） |
| 金额 | VARCHAR(64)，注释标注单位（万元） |
| 长文本 | 审批意见、整改说明、经营范围、规则描述等用 TEXT |
| 时间 | VARCHAR(32)，格式 yyyy-MM-dd HH:mm:ss（与下游接口返回保持对齐） |
| 多期数据 | **一期一行**：表内带会计月/查询时间/统计月份等期字段 |

## 六、复用设计（重点）

### 6.1 元属性复用——下沉公共表

Excel 中"会计月/报表类型/报表口径/报表周期"出现在 **11 个模块**、"征信查询时间"出现在 **7 个模块**。若每张模块表都存一遍将无法维护。方案：

- `app_finance_report_info`：一期报表一行（reportNo + 会计月 + 报表类型 + 口径 + 周期 + 是否审计 + 币种），**全部 7 个"重点财务指标分析"模块及征信交叉解读共用它**；
- `app_credit_report_info`：queryTime（查询时间）+ 报告有效期，经验库"征信报告是否在有效期内"规则直接读它判断。

模块表（如 app_finance_index_info、app_credit_debt_detail）只存指标值，通过 `reportNo + accountMonth / queryTime` 关联回主档，不重复存储元属性。

### 6.2 实体复用——实体只存一张表

同一实体被多个模块消费时，实体数据只落一张表：

- **押品**：正文文案（押品风险解读）取评估价值/顺位；经验库规则"授信后新增顺位抵押"判断 rightOrder/registerTimestamp；表格列全部押品 → 全部来自 app_collateral_info + app_collateral_mortgage_info；
- **借据**：业务产品情况（文案+表格）、逾期情况、经验库"贷款用于归还股东借款"规则 → 全部来自 app_loan_receipt_info；
- **股东（工商口径·最新）**：工商情况及股权结构（文案）→ 来自 app_shareholder_info（股东名/持股/出资/持股比例/是否已出资/是否国资/是否假冒国企/是否上市）；
- **股东（信贷系统口径）**：信贷系统维护的股东 → app_xd_shareholder_info（股东名/持股比例/出资方式/应出资金额/投资时间）；
- **股东（工商口径）**：经验库"股权变更/假冒国企/工商受益人≠系统实控人"规则 → 股东名/持股/变更来自 app_ic_shareholder_info，受益人/国企标识来自 app_ic_info，与系统口径分开存储，规则分别取数后比较。

### 6.3 指标复用——字段同时服务三端

同一指标（营收同比、净利润、短期借款等）既被规则阈值判断，又被正文文案引用、被表格列出。**不按展现形式分表**，指标表（app_finance_index_info）一份数据，规则引擎、文案引擎、表格组件按需取同一列。设计时已把"规则判断字段"显式建列并注释（如 indexValue、yoyValue），公司做规则配置时直接引用字段名。

### 6.4 经验库规则：只提供源数据，不建规则表

经验库（C 列=经验库）的规则模块**不单独设计规则相关表**。做法与正文模块一致：按每个经验库模块的数据要素，梳理出规则判断所需源数据——来自哪些表、哪些字段、SQL 怎么查（详见《数据映射细化V4.xlsx》各经验库模块）。规则触发逻辑的命中计算、结果存储、溯源采纳由**公司规则平台自行设计**，本表结构提供其所需的数据基础。

**工商/系统双口径对比**（如"工商受益人≠系统实控人""工商法定代表人≠系统法定代表人""工商股东名称≠系统股东名称"）：工商口径取 app_ic_info（法代/受益人）/ app_shareholder_info（工商股东最新）/ app_ic_shareholder_info（工商股东变更）、系统口径取 app_customer_info / app_xd_shareholder_info（信贷系统股东；实际控制人为 app_customer_info.actualController），两套数据分表存储、分别取数，规则引擎拿到两个值后自行比较——两口径绝不共用同一字段。

## 八、时间窗口与"一期一行"

Excel N 列时间窗口覆盖 17 种取值，处理规则：

- **最新 / 最新一期**：单值字段直接存最新；
- **授信时 / 上年 / 上上年 / 每月**：走"一期一行"（表内期字段：accountMonth / statMonth / taxPeriod / queryTime），规则和文案按需取 `WHERE 期 = 目标期`；
- **授信时 vs 最新对比**（股权变更、工商受益人判断）：工商股东变更在 app_ic_shareholder_info（`snapshot_type` + 变更前后比例）；工商股东最新在 app_shareholder_info、信贷系统股东在 app_xd_shareholder_info；财务指标授信时点通过 app_credit_use_info.creditDate 反查报表期。

## 九、待确认项（公司需与数据源确认后补入）

1. **结算账户类**：账号、账户状态、账户余额、冻结金额、年日均存款、监管标识 —— 接口待确认（app_settle_account_info 已预留全部字段）；
2. **工商/税务/舆情中台类**：工商法定代表人、工商股东、工商受益人、工商注册资本、工商实缴资本、假冒国企、借款人/股东是否上市公司、舆情事件（类型/时间）、国税最新一期、纳税销售额 —— 接口待确认（工商客户级在 **app_ic_info**、工商股东在 **app_ic_shareholder_info**、是否上市公司在 app_customer_info / app_shareholder_info / app_guarantor_info、舆情事件在 **app_reputation_event_info**、税务在 app_tax_info，已预留字段）；
3. **财务指标子字段**：营业收入、净利润、借款、应收应付等具体科目值 —— 接口已定（获取客户财报查询接口），子字段待细化（app_finance_index_info 以 indexType 行式承载，无需改表，直接加指标类型即可扩展）；
4. **"同'六、征信情况和潜在风险'"引用型要素**：担保人征信场景直接复用 app_credit_report_info / app_credit_debt_detail 同结构，公司可按担保人扩展 guarantorName 维度。

## 十、扩展性说明

- 新增财务指标科目：app_finance_index_info 增加一行 indexType 即可，**无需改表结构**；
- 新增征信债务类型：app_credit_debt_detail 增加 debtType 行即可；
- 新增经验库规则：直接从现有表取源数据，无需新增规则表（命中结果存储由公司规则平台设计）；
- "待确认"数据源确认后：仅补来源接口映射，表结构不变。
